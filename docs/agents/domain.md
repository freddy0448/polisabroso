# Domain docs

## Before exploring the codebase

This repository uses a single-context layout:

- Read root `GLOSSARY.md` for domain vocabulary.
- Read relevant decisions under `docs/adr/`.

If these files do not exist, proceed silently. Create them through
domain-modeling when terminology or decisions are resolved.

## Use the glossary's vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider the terminology or note the
gap for domain-modeling.

## Flag ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR.
Name the ADR and explain why its decision should be reconsidered.
